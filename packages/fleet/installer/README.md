The shared installer is [modules/installer.nix](../modules/installer.nix) plus [modules/installer-iso.nix](../modules/installer-iso.nix). The `Fleet` workflow builds `.#installer`, uploads a 14-day Actions artifact, and publishes the same ISO to the `fleet-installer` release so the download does not expire. A new machine runs [scripts/fleet-node.sh](../scripts/fleet-node.sh): one file, no Nix, no checkout. It fetches that release and installs an active role from [`roles.json`](../roles.json) (`ci` or `devbox`) only after the role and the internal disk are confirmed. `just build-iso` still builds it locally when a Linux builder is available. `just fetch-iso` is the legacy artifact download.

The ISO contains the closures `roles.json` marks `installer` (`ci` and `devbox`) and a manifest at `/fleet-install-manifest` (the live system reads `/iso/fleet-install-manifest`). It does not contain `ci-gpu` or an age key. The first boot entry is `installerDefault` (`ci`); every other entry passes its own `fleet.role=`. `fleet-auto` then wipes the one internal disk `select-disk` chose and installs that closure. SSH uses [settings/installer.nix](../settings/installer.nix) and is optional. One USB boots every role on the image, from Windows, Linux, or an empty disk. `fleet-auto` exits without wiping when the manifest is absent.

Booting the installer ISO wipes the internal disk. The live image has no fleet hostname. There is no remote reinstall; run `fleet-node` on the machine.

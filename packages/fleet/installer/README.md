The shared installer is [modules/installer.nix](../modules/installer.nix) plus [modules/installer-iso.nix](../modules/installer-iso.nix). The `Fleet` workflow builds `.#installer`, uploads a 14-day Actions artifact, and publishes the same ISO to the `fleet-installer` release so the download does not expire. A new machine runs [scripts/fleet-node.sh](../scripts/fleet-node.sh): one file, no Nix, no checkout. It fetches that release and installs the role-less `base` system only after the internal disk is confirmed. The role is assigned later in the Fleet app. `just build-iso` still builds it locally when a Linux builder is available. `just fetch-iso` is the legacy artifact download.

The ISO contains only the `base` closure plus disko, and a manifest at `/fleet-install-manifest` (the live system reads `/iso/fleet-install-manifest`) with two lines: `base <toplevel>` and `disko <path>`. It does not contain any role closure or an age key. The boot menu has one entry, with no `fleet.role=`. `fleet-auto` then wipes the one internal disk `select-disk` chose and installs `base`. SSH uses [settings/installer.nix](../settings/installer.nix) and is optional. One USB installs every node, from Windows, Linux, or an empty disk. `fleet-auto` exits without wiping when the manifest is absent.

A fleet that follows a private Git repository (`repoAuth` `ssh` or `token` in the base closure's `/etc/fleet/bootstrap.json`) needs its read credential: `fleet-install` takes it from `FLEET_GIT_CREDENTIAL_FILE`, the private handoff (`fleet-git-credential`) or `git-read-key` / `git-read-token` on a `FLEET-KEY` volume, refuses before erasing without one of the matching kind, and installs it to `/nix/fleet-state/secrets/git-read-key` or `git-read-token` (0600).

Booting the installer ISO wipes the internal disk. The live image has no fleet hostname. There is no remote reinstall; run `fleet-node` on the machine.
